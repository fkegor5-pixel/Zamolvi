# Сборка APK

## Как собирается приложение

Zamolvi собирается поверх базового приложения `base/base-app-2.7.apk`. В нём
главное меню и разделы 1–9 (VPS, Telegram, AI, чаты, автоответчик, журнал,
статистика, тема). Его скомпилированный код при сборке **не меняется**. Скрипт
`build-tools/build_apk.py`:

1. распаковывает ресурсы и манифест базового APK (Apktool, без декомпиляции кода);
2. компилирует `source/*.java` в отдельный `classes2.dex`; классы базового
   приложения, к которым обращаются новые экраны, описаны в `compile-api/`
   (только для компиляции, в APK не попадают);
3. добавляет в манифест новые экраны, виджет, плитку и уведомление, задаёт
   название и версию;
4. упаковывает `server/` в `assets/replyai-server.bundle` — эту версию сервера
   приложение ставит на VPS;
5. собирает, выравнивает и подписывает APK и проверяет, что код базового
   приложения и идентификаторы его ресурсов не изменились.

## Локальная сборка

Нужны Python 3.10+, JDK 17+, Android SDK (platform `android-35`, build-tools 35)
и [Apktool](https://apktool.org) 3.x.

```bash
python3 build-tools/build_apk.py --sdk "$ANDROID_HOME" --apktool /path/to/apktool.jar
```

Результат — `build/Zamolvi-3.0.apk`.

## Ключ подписи

Android устанавливает обновление поверх приложения, только если оно подписано
**тем же ключом**. Поэтому ключ нужно хранить и использовать для каждой сборки.

- По умолчанию берётся `signing/release.p12` (каталог `signing/` в `.gitignore`).
  Если файла нет, скрипт создаст новый ключ.
- Свой ключ: `--keystore путь.p12` или переменная `ZAMOLVI_KEYSTORE`,
  пароль — `ZAMOLVI_KEYSTORE_PASSWORD`, псевдоним — `ZAMOLVI_KEY_ALIAS`.

**Никогда не добавляйте ключ подписи в репозиторий.** Кто получит ключ, сможет
выпустить «обновление» вашего приложения.

## Сборка в GitHub Actions

Workflow `.github/workflows/build.yml` собирает APK на серверах GitHub:

- вручную: вкладка **Actions → Build APK → Run workflow**; APK появится в
  артефактах запуска;
- при публикации тега `v*` (например, `v3.0`): APK прикрепляется к релизу.

Чтобы сборки из Actions ставились поверх уже установленного приложения, добавьте
свой ключ в **Settings → Secrets and variables → Actions**:

| Секрет | Значение |
|---|---|
| `SIGNING_KEYSTORE_BASE64` | файл `.p12` в base64: `base64 -w0 release.p12` |
| `SIGNING_KEYSTORE_PASSWORD` | пароль хранилища |
| `SIGNING_KEY_ALIAS` | псевдоним ключа |

Без секретов workflow подпишет APK временным ключом: такую сборку можно
установить только начисто, она не обновит приложение с другой подписью.
